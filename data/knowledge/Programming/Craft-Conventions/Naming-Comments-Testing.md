# Naming, Comments, Testing Conventions

## Naming

Be consistent and readable. One convention from the notes: **const** values often use ALL_CAPS style.

## Comments

Comment *why* and non-obvious intent; don’t narrate obvious code.

## Testing (TDD-adjacent)

- Prefer tests as a habit, not an afterthought.  
- Cover edge cases.  
- Compile/run unit tests as part of the workflow (“Compiling Unit tests” in the source notes).
