# Imperative Programming

Developers explicitly define **steps and control flow** — how to perform operations through state changes and sequential instructions.

## Core ideas

- Direct manipulation of program state
- Loops, conditionals, assignments as primary tools
- You own the “how”

## Trade-offs

Strong for clear, local control. Can become harder to maintain and scale when mutable state and control flow sprawl.

## Contrast

Declarative programming states *what* without prescribing *how* (e.g. SQL).
