# FP — Functional Programming

A paradigm based on **mathematical functions**: computation as evaluating functions.

## Core ideas

- Prefer **pure functions** (same input → same output, no hidden effects)
- Prefer **immutable** data
- Avoid / isolate **side effects**
- Compose small functions into larger behavior
- Higher-order functions (map, filter, reduce, …)

## When it helps

Predictable transforms, easier testing of pure logic, concurrent-friendly code when shared state is minimized.
